# 04. サイト一覧画面の視認性向上

## 目的

`/sites`のサイト一覧が、サイト数の増加に伴って見づらくなっている問題を解消する。バックエンド・データモデルの変更は行わず、フロントエンドの表示のみを改善するスコープとする。

## 現状確認(具体的な問題点)

現状の実装は[web/src/app/sites/page.tsx](../../web/src/app/sites/page.tsx)で、サーバーコンポーネントが1本のテーブルを描画するのみ:

- 検索・絞り込みの手段が一切ない。サイトキー/表示名/URL/CMS種別/プロジェクト紐付けのいずれでも絞り込めず、登録件数が増えるとお目当てのサイトを探すのに全行を目視する必要がある
- プロジェクトへの紐付け状況(`siteToProject`)がテキスト表示(`"{プロジェクト名}({環境名})"`または`"-"`)のみで、紐付き/未紐付きの視覚的な区別がなく一覧性が低い(`page.tsx:72-74`)
- CMS種別バッジ(`bg-blue-100`/`bg-green-100`)と自動構築バッジ(`bg-amber-100`)が同じセル内に並記されており(`page.tsx:58-70`)、他のカラムと視覚的な重み付けが同じで目立つべき情報(未紐付き・疎通失敗等)が埋もれる
- URL列(`page.tsx:75-79`)が折り返し・省略なしでそのまま表示されるため、長い外部URLが入ると列幅が崩れテーブル全体が横に伸びる
- 疎通確認(`CheckConnectionButton`)はボタン押下時のその場結果表示のみで、行全体に対する視覚的なステータス表現(失敗行を目立たせる等)がない(Phase10の決定事項により結果は永続化しないため、リロードで消えるのは仕様通りで変更しない)
- テーブルヘッダーがスクロール時に固定されず、行数が増えるとどの列が何を表しているか分かりにくい
- 全行が同じ背景色で、ゼブラストライプやホバー時のハイライトがなく、視線が横方向に流れやすい(行の誤読につながる)

## 前提・決定事項

| 項目 | 決定内容 |
|---|---|
| スコープ | フロントエンドの表示改善のみ。API・DTO・データモデルの変更は行わない |
| 実現方式 | `page.tsx`(サーバーコンポーネント、データ取得のみ)から表部分を`SiteListTable.tsx`(新規クライアントコンポーネント)へ切り出し、検索・絞り込みをクライアント側の状態(`useState`)で行う。サーバーサイド検索API・ページネーションAPIは追加しない(既存の`listSites()`が返す全件をクライアント側でフィルタする) |
| 検索・絞り込み | テキスト検索(サイトキー・表示名・URLの部分一致、大文字小文字を無視)、CMS種別フィルタ、プロジェクト紐付け有無フィルタの3つを組み合わせ可能にする |
| 大量データへの対応 | 仮想スクロール・サーバーサイドページネーションは本タスクのスコープ外(将来、件数が実運用上問題になった時点で再検討) |
| 疎通確認結果の永続化 | 変更しない(Phase10の決定を踏襲し、引き続き非永続・都度チェック) |

## アーキテクチャ・実装詳細

### コンポーネント分割

`web/src/app/sites/page.tsx`(サーバーコンポーネント、データ取得のみに簡素化):

```tsx
export default async function SitesPage() {
  const [sites, projects, users, session] = await Promise.all([...]);
  const isAdmin = session?.user.role === "admin";

  return (
    <div className="space-y-8">
      <h1 className="text-xl font-semibold">サイト</h1>
      <SiteListTable sites={sites} projects={projects} isAdmin={isAdmin} />
      <SiteCreationPanel users={users} sites={sites} />
    </div>
  );
}
```

`web/src/app/sites/SiteListTable.tsx`(新規、クライアントコンポーネント):

- `sites`/`projects`から`siteToProject`マップを構築する処理を`page.tsx`から移設
- 検索テキスト入力(サイトキー/表示名/URL部分一致)、CMS種別`<select>`(すべて/WORDPRESS/MICROCMS)、プロジェクト紐付け`<select>`(すべて/紐付け済み/未紐付け)の3つのフィルタUIをテーブル上部に配置
- フィルタ適用後の件数(例: 「12件中5件を表示」)を表示
- プロジェクトに紐付いている行は環境バッジ(ローカル=緑・テスト=黄・本番=赤、`EnvironmentSyncPanel.tsx`等で使われている環境ラベルと统一)+プロジェクト名を1つのセルにまとめて表示し、未紐付きの行は薄いグレーの「未紐付け」バッジのみを表示する(現状のテキスト`"{name}({env})"`/`"-"`表示を置き換え)
- CMS種別・自動構築バッジは維持しつつ、Tailwindの`sticky top-0`をヘッダー行に付与しスクロール時も列名が見えるようにする
- 行に`odd:bg-neutral-50`(ゼブラストライプ)・`hover:bg-neutral-100`(ホバーハイライト)を追加
- URL列は`truncate max-w-xs`で省略表示し、`title`属性でフルURLをツールチップ表示する(クリック時の遷移先は変更なし)
- 既存の`CheckConnectionButton`・`DeleteSiteButton`・編集リンクの配置・機能は変更しない(表示スタイルの調整のみ)

### `SiteCreationPanel.tsx`への`sites` prop追加

[03-wordpress-template-clone.md](03-wordpress-template-clone.md)でテンプレート選択のために`sites`をpropsで受け渡す変更が入る予定のため、本タスクを03より先に着手する場合は`page.tsx`の`<SiteCreationPanel users={users} />`はそのまま(`sites`追加は03側の変更)。03が先行完了している場合はコンフリクトしないよう、本タスクでは`page.tsx`の該当行を上書きしないよう注意する(実装順序に依存しないよう、03のdiffと本タスクのdiffが両立することを実装時に確認する)。

## スコープ・実装項目

実装対象:

- [ ] `web/src/app/sites/SiteListTable.tsx`(新規)
- [ ] `web/src/app/sites/page.tsx`: テーブル部分を`SiteListTable`へ切り出し
- [ ] 検索・絞り込みUI(テキスト検索・CMS種別・プロジェクト紐付け有無)
- [ ] 環境バッジ・未紐付けバッジの追加
- [ ] sticky header・ゼブラストライプ・ホバーハイライト
- [ ] URL列の省略表示(`title`属性でフルURL表示)

対象外・スコープ外:

- サーバーサイド検索・ページネーション・仮想スクロール
- 疎通確認結果の永続化・行の恒常的なステータス表示
- ソート機能(列ヘッダークリックによる並び替え)
- サイト一覧のCSVエクスポート等の付随機能

## 実装順序

1. `SiteListTable.tsx`の新規作成(検索・絞り込みロジック含む)
2. `page.tsx`からテーブル部分を移設
3. スタイル調整(sticky header・ゼブラストライプ・バッジ・URL省略)
4. 実機確認

## テスト整備

- 本タスクはUIのみの変更でありユニットテストの追加は必須としない。目視確認を実機検証で代替する

## 実機検証

1. サイトを10件以上登録した状態で`/sites`を開き、検索ボックスにサイトキーの一部を入力して絞り込めることを確認
2. CMS種別フィルタ・プロジェクト紐付けフィルタを組み合わせて絞り込めることを確認
3. プロジェクトに紐づいているサイトと未紐付けのサイトが一目で区別できることを確認
4. テーブルをスクロールした際にヘッダー行が固定表示されることを確認
5. 既存機能(疎通確認・編集・削除・サイト登録)がすべて従来通り動作することを確認(表示の変更のみで機能退行がないこと)
