# 手で貼った CSS から letsblog プラグインの CSS 配信への移行

Lets Blog の letsblog プラグインは、同期済みの統合 CSS(カスタムタグ・グローバルタグ・目次/ブログカード/Amazon などの組み込みタグのデザイン CSS)を、サイトの表側で自動的に読み込みます(issue #1559)。あわせて、記事本文の囲み `<div class="lets-blog-rendered {prefix}">` の `{prefix}` を、表示時に現在の `cssSelectorPrefix` へ付け直します。

これまでテーマの追加 CSS などへ手で貼っていた CSS は、プラグインの CSS と**二重に適用される**ため、移行時に取り除いてください。プラグインは手で貼った CSS を自動では削除しません。

## 手順

1. プラグインが導入済みで、アプリの「サイト編集」から同期済みであることを確認する(`wp letsblog status` の `sync_hash` が `null` でない)。
2. 表側のページを開き、ページのソースに `letsblog-synced-inline-css` を持つ `<style>` があることを確認する。
3. WordPress の管理画面(外観 > カスタマイズ > 追加 CSS、またはテーマ/子テーマの CSS、ヘッダー挿入系プラグイン)から、以前アプリの統合 CSS を貼った部分を取り除く。二重に適用されないようにするためで、取り除いたあとも見た目が変わらないことを確認する。
4. 以後、アプリでタグの CSS や `cssSelectorPrefix` を変えても、再同期だけで既存記事に反映される。再投稿や CSS の貼り直しは不要。

## 補足

- プラグインを停止すると、プラグインが登録したフックごと無くなり、CSS は読み込まれません。同時に囲みクラスの付け直しも行われないため、記事本文には投稿時点のクラスが残ります。
- 同期前(`wp letsblog sync` を一度も受け取っていない)のサイトでは、プラグインは CSS を読み込まず、本文も書き換えません。手で貼った CSS はその間は残しておいて構いません。
