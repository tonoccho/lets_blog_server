# 外部 Penpot の到達性を連携サービスの状況に出す

Let's Blog は Penpot を同梱しない(issue #1749 / #1750 / #1752)。LAN 内で別途起動した Penpot の URL を
システム設定に1つ登録すると、連携サービスの状況に **Penpot が動いているか(到達できるか)** だけが表示される。
デザインファイルの作成・取り込み、Penpot のプラグインや MCP サーバーは行わない。Penpot の起動・運用手順は
本書の範囲外である。

## 設定項目

システム設定画面(管理者)の「外部Penpot連携」にある **Penpot ベースURL**(`system_settings` のキー `penpot_base_url`)。

| 項目 | 内容 |
| --- | --- |
| 値 | Penpot の URL(例: `http://192.168.1.80:9001`)。`http://` または `https://` で始める |
| 範囲 | システム全体に1つ。プロジェクト単位の上書きは無い |
| 認証 | 持たない。トークンやサービスアカウントは登録できない |
| 未設定に戻す | 空欄で保存する。環境変数の既定値は無い |

## 接続先の検査

保存時と接続時(状況の確認のたび)に、接続先を `ConnectionDestinationGuard` で検査する。
LAN のプライベートアドレス(`192.168.x.x` など)は通る。次は保存できず、接続もしない。

- loopback(`127.0.0.1`、`localhost`)・未指定アドレス・リンクローカル(`169.254.0.0/16`。クラウドのメタデータを含む)
- Let's Blog 自身が参加する docker ネットワーク内のアドレス
- 名前解決できないホスト名

インターネット上の Penpot(クラウド版を含む)への接続は対象外である。

## 連携サービスの状況での表示

到達性は、設定した URL のルート(`GET /`)への HTTP リクエスト1回で判定する。タイムアウトは 3 秒で、再試行しない。

| 状態 | 表示 | 理由の表示(管理者) |
| --- | --- | --- |
| URL が未設定 | 警告 | 「未設定(システム設定で設定してください)」 |
| HTTP 応答がある(4xx を含む) | 正常 | なし |
| 5xx の応答 | 警告 | 異常な応答(HTTP ステータス) |
| 接続できない・タイムアウト・検査で拒否 | エラー | 到達できない理由 |

他のサービスの行の判定は変わらない。理由は、管理者がトップページの連携サービスの状況に表示される行(および
「管理者向け詳細診断」)で確認できる。
