# ADR-0011: LLM・画像生成・図のレンダリングは、契約 API(HTTP)で話す外部プラグインにする

- **日付**: 2026-10-13
- **関連**: #1755(Epic)、#1756、#1745 / #1746(同梱コンテナの削除)、#1753(外部 Penpot)、#1572(SNS 告知)、
  #1762 / #1763(接続先の自動設定の経路)
- **改訂**: 認証の決定(CONTRACTS.md §0・§4.2)は [ADR-0012](0012-extensions-tools-keycloak-auth.md) が改訂した(2026-10-15)
- **契約の中身**: [docs/plugins/CONTRACTS.md](../plugins/CONTRACTS.md)(本 ADR にはエンドポイントやペイロードを書かない)

## 状態 (Status)

採用(Accepted)。2026-10-13。

## 背景 (Context)

利用者の要望(2026-10-11、原文):「プロダクトとして持つべき機能は1~5です。これらは保持する必要があります。
6~8については『外部サービスをプラグインする』という形にしたいです。9はプラグインの機能として提供、
10はダッシュボードとして持っておきたいです。」

| # | 機能 | 扱い |
| --- | --- | --- |
| 1 | 執筆(VS Code 拡張) | 中核 |
| 2 | WordPress 公開 | 中核 |
| 3 | レビュー・承認 | 中核 |
| 4 | 記事の組み立て(content・カスタムタグ) | 中核 |
| 5 | 利用者・権限・認証 | 中核 |
| 6 | AI 執筆支援(LLM) | 外部プラグイン |
| 7 | 画像生成 | 外部プラグイン |
| 8 | 図のレンダリング | 外部プラグイン |
| 9 | SNS 告知 | WordPress プラグインのまま(現状維持) |
| 10 | GA / AdSense | 中核(ダッシュボード) |

現状の中核は、6〜8 の提供元ごとのクライアントを抱えている(2026-10-13 の `develop` で確認)。

- `services/ai` の `LlmClient` は、Ollama / OpenAI へ OpenAI 互換 API を、Claude へ Anthropic Messages API を直接話す。
  Ollama 固有の `/api/tags`(モデル一覧)・`/api/pull`(モデル取得)・`/api/ps`(演算デバイス)も中核が持つ。
  画像入力の可否はモデル名の許可リスト(`VisionSupport`)で推定している。
- `services/media` の画像生成は、ComfyUI のワークフロー組み立て(`ComfyUiClient`)と OpenAI Images API(`ChatGptImageClient`)を
  中核が持ち、引数も ComfyUI 固有の指定(steps / cfgScale / sampler / LoRA / チェックポイント)が中心である。
- 図は、同梱の PlantUML サーバー、`services/media` 内のヘッドレス Chromium による Recharts、同梱の draw.io を使う。
- Ollama / ComfyUI の同梱コンテナは #1745 / #1746 で、Penpot は #1748〜#1752 で消えた。接続先は URL で指す形になっており、
  「外部のサービスを URL で指す」土台(システム設定 #1567、プロジェクト単位の上書き #1503、秘密の暗号化 `CredentialCipher`、
  接続先の検査 `ConnectionDestinationGuard`)はすでにある。

境界と契約が決まっていないため、LLM・画像生成・図のレンダリングの後続の子 Issue は要件を書けない。

## 決定 (Decision)

### 1. 境界

- **1〜5 と 10 は中核が持つ。**
- **6〜8(LLM・画像生成・図のレンダリング)は、中核が定める契約 API(HTTP)を話す外部プラグインにする。**
  提供元ごとの違いは、プラグイン(アダプター)が中核の外で吸収する。中核に提供元固有のクライアントを持たない。
- **9(SNS 告知)は今のまま WordPress プラグイン(`infra/wordpress/letsblog-plugin/letsblog.php`、#1572)で行う。**
  Webhook 方式は採らず、SNS には契約も登録も作らない。本 Epic の対象外。
- 登録できるプラグインの種類は **LLM / 画像生成 / 図のレンダリング / Penpot** の4つ。Penpot は種類として名前を挙げるだけで、
  契約の中身と連携の範囲は #1753 で決める。
- Brave Search と GitHub 連携は利用者の分類に挙がっていないため、今のまま中核に残す(Epic #1755 の既定)。

### 2. 利用者の決定(2026-10-11)

1. **契約 API 方式**: 中核は契約 API(HTTP)を定める。LLM の契約は OpenAI 互換 API をそのまま使う。
   外部 Penpot への再接続(#1753)も同じ登録の仕組みに乗せる。
2. **図のプラグインが未接続のとき**: 図のカスタムタグを含む記事を公開しようとしたら、**公開の前に**(CMS へ書き込む前に)
   理由の分かるエラーで止める。
3. **SNS 告知**: WordPress プラグインのまま。Webhook 方式は採らない。

### 4. プラグインの登録

- 登録は、種類・接続先 URL・認証情報(任意)で表す。単位は**システム全体**と**プロジェクト単位の上書き**で、
  既存の `system_settings`(#1567)とプロジェクト単位の上書き(#1503)の型に従う(解決順: プロジェクト → システム → 未接続。環境変数へはフォールバックしない)。
- 認証情報は `CredentialCipher` で暗号化して保存し、接続先は `ConnectionDestinationGuard` で保存時と接続時に検査する。
- プラグインが何をできるかは、プラグインが**能力として宣言**する(使えるモデル、画像入力の可否、画像生成の追加パラメータ、
  対応する図の記法)。中核は提供元の名前から推測しない。
- 詳細(項目・解決順・能力の形式)は契約文書の「プラグインの登録」に書く。

### 5. 登録先を見つける元の候補: `lets_blog_server_extensions` の `GET /api/connections`

利用者の決定(2026-10-12): `lets_blog_server_extensions`(`seiji/lets_blog_server_extensions`)のポータルの `GET /api/connections` から
接続先を自動で設定する機能を、本 ADR のマージ後に「プラグインの登録」の一部として作る(Epic #1755 の子)。
この API を**プラグインの登録先を見つける元の候補**として記録する。

- 返す項目は `id` / `name` / `publicUrl` / `internalUrl` / `internalServiceUrl`。Ollama だけ `openaiBaseUrl` も返す。認証はない。
- 契約ではない(中核が話す相手の契約は契約文書)。どの `id` をどの種類へ対応づけるか、どの URL を使うかは、
  同じ PC での接続経路(#1762)と別ホストでの接続経路(#1763)を扱う子 Issue で決める。
- 認証がなく認証情報を返さないので、見つけた接続先も手で登録した接続先と同じく `ConnectionDestinationGuard` を通す。

## 影響 (Consequences)

得るもの:

- 中核から提供元固有のコード(Anthropic・Ollama 固有 API・ComfyUI のワークフロー・PlantUML サーバー・Chromium)が消え、
  提供元を増やしても中核を変えない。LLM と ChatGPT 画像生成は OpenAI 互換なのでアダプター不要で、Ollama / OpenAI へはそのままつながる。
- 画像入力の可否を、モデル名の推測ではなく宣言で知れる。
- 図の未接続は、公開の前に理由つきで止まる。

失うもの・負担:

- アダプターが要るもの(ComfyUI・Claude・PlantUML サーバー・Recharts)は、このリポジトリで作り、利用者が自分で動かす。
  利用者の運用の手間が増える(compose へは同梱しない)。
- 図のレンダリングは「プラグインを動かしていないと公開できない」ことになる(PlantUML / Recharts を使う記事のみ)。
- 中核が外部呼び出しの失敗を扱う面が増える(未接続・不到達・能力の変化)。
- 現在の挙動が変わる: PlantUML の画像アップロードは途中で WordPress に書き込むため、公開の停止は
  レンダリングを CMS 書き込みの前へ寄せる改修を要する(契約文書に手順を書く)。
- 子 Issue の数が多い(Epic #1755 の「計画中」。棚卸しは契約文書の「棚卸し」)。
- 既存の環境のプロバイダー設定(API キー、Ollama / ComfyUI の URL、選択中のプロバイダー)を登録へ移行する作業がある。

## 検討した代替案 (Alternatives considered)

| 案 | 却下の理由 |
| --- | --- |
| **中核に各提供元のクライアントを持ち続ける(現状)** | 提供元ごとに中核を直す必要が続く。Ollama 固有 API(pull / ps)や ComfyUI のワークフローのように、提供元固有の画面と API が中核に増え続ける。利用者の要望(6〜8 はプラグイン)に反する。直接つながる OpenAI 互換の部分は契約クライアントとして残るので、そこは現状と変わらない |
| **RabbitMQ を外部へ公開する**(プラグインがイベント・要求を購読する) | RabbitMQ は中核のサービス間の内部の仕組みで、認証・ネットワークの境界を外へ広げることになる。要求と応答の形(同期の LLM・画像・図のレンダリング)は HTTP のほうが素直で、OpenAI 互換や PlantUML 等の既存の API とも揃う。公開イベント(`PostPublishedEvent`)は fire-and-forget で応答を返せない |
| **SNS 告知も Webhook 契約でプラグイン化する** | 利用者が却下(2026-10-11): WordPress プラグインのまま。署名方式などの設計が増えるだけで得るものが無い |
| **契約を独自の形にして、OpenAI 互換のサービスにもアダプターを挟む** | Ollama・OpenAI は OpenAI 互換をそのまま話せるので、不要な中間層とアダプターの数が増える |
| **ComfyUI 固有の指定を契約に載せる / 画面から外す** | Q3 で利用者は「宣言された追加パラメータだけ画面に出す」を選んだ。契約に載せると他の提供元で意味を持たず、画面から外すと既存の機能が失われる |
| **アダプターを Let's Blog の compose に同梱する** | Q2 で利用者が却下(動かす場所は利用者が決める)。GPU PC で ComfyUI と並べる運用を妨げる |
